Palletizing Start is used to set the information of stock which will be palletized by robot automatically.

Palletizing Setting web screen is accessed and used by user when JDE is not available due to service disruption. After **Set(F2)**, all items in Details list will be added into a Pallet Number. The Purchase Order generated for this pallet number will be categorized as Unplanned and no result will be posted back to JDE.

## Validations
- Storer Code exists in DMSTORER.
- Short ID exists in DMITEM
- Qty in Primary UOM is not larger than System set limit.
- Details list is not empty

To perform RFT Putaway to Conventional Warehouse, user need to complete such act with RFT Putaway. User is required to scan Pallet Label and provide Type 1 then proceed with **Pick(F2)**.

If Pallet Label scanned and provided Type is valid, user will be brought to next screen after **Pick(F2)**. In the second screen, WareNavi will assign a Location or user can manually provide a location number by clicking on **Manual** button. Then user is required to perform physical Location Barcode scan to ensure user is at the physical location to putaway.

After all inputs are provided, user click on **Confirm(F4)** to confirm putaway of Pallet at provided Location Number.

## Validations
- Storer Code is NOT undergoing Inventory Check.
- Location No. is empty. (DMLocate.STATUS_FLAG.EMPTY)
- Location and Confirm Loc. are the same.
- Purchase Order is NOT cancelled. (DNStoragePlan.STATUS_FLAG.DELETE)
- Pallet has not completed Storage. (DNPallet.STATUS_FLAG.REGULAR)
- Pallet is not reserved for Direct Ship. (DNPallet.STATUS_FLAG.RETRIEVAL_PLAN)
- Pallet number is under QC_FLAG = 0:Verified
- Pallet Information does not exist in DNCARRYINFO.
To check for Pallet Information:
JOIN DNCARRYINFO.PALLET_ID = DNPALLET.PALLET_ID
CONDITION DNPALLET.BCR_DATA = <Pallet Number>
So if result > 0, RFT Putaway cannot proceed.
